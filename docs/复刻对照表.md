# 复刻对照表：原软件行为 → 本工程实现 → 验证方式

本表逐项对齐 `docs/analysis/` 里的逆向规格（左侧）与本工程代码（中间），并写清每一项怎么验证（右侧）。`状态` 一栏的含义：**已实现** 表示代码存在且构建通过；**已验证** 表示有自动化证据（JVM 自测或设备脚本产出）；**差异** 表示有意与原软件不同，原因见 `docs/analysis/spec/02-开源复刻方案.md`。

## 2. 模拟状态机与 1 秒 tick

| 原软件行为（规格） | 本工程实现 | 验证方式 | 状态 |
|---|---|---|---|
| tick 固定 1000 ms，位移用 `elapsedRealtime` 真实时间差累计 | `onTick()`：`deltaSeconds = (now - lastTickElapsedMs)/1000` | JVM 自测覆盖路线推进公式；设备脚本第 5 步观察坐标移动 | 已验证（公式）/ 已实现（系统行为） |
| 单点模式每秒原样注入，速度 0、方位 0 | `onTick()` 的 STATIC 分支 | 设备脚本第 4 步 | 已实现 |
| 暂停时仍每秒 tick、仍注入，但速度为 0，且不累加已走距离 | `onTick()`：`if (!paused && !completed) traveled += ...`；`MockState.injectedSpeedMps()` 在暂停/完成时返回 0 | 设备脚本第 6 步：暂停后坐标不变 | 已实现 |
| 循环用「已走距离对总长取模」，永不置完成 | `onTick()`：`traveledMeters %= total`；`RouteEngine.positionAt(traveled, loop)` | JVM 自测：1250 m 在 1000 m 环线回到 250 m，永不 finished | 已验证 |
| 非循环走完：traveled 夹到 total，routeCompleted=true，注入速度 0，但 isRunning 仍为 true，继续每秒注入终点 | `onTick()`：`completed = position.finished && !loop`；状态保留 `running=true`，`routeCompleted=true`；注入速度 0 | JVM 自测：终点坐标/进度/结束标志；设备脚本可选 | 已验证（算法） |
| 单点启动立刻注入第一帧 | `startSingleMock()` 中 `scheduleTick(0)` | 设备脚本第 4 步（4 秒内取样） | 已实现 |
| START_MOCK 缺经纬度 extra 时 stopSelf 并返回 START_NOT_STICKY | `onStartCommand()` 的 ACTION_START_MOCK 分支 | 代码审查 | 已实现 |
| 路线点数 <2、速度 <=0、总长 <=0.01 m 判无效 | `startRoute()` 校验 + `RouteEngine` 构造校验（MIN_TOTAL_METERS=0.01） | JVM 自测构造非法路线 | 已验证 |
| 运行中 `onStartCommand` 返回 START_REDELIVER_INTENT，否则 START_NOT_STICKY | `onStartCommand()` 末尾三元返回 | 代码审查 | 已实现 |

> 为了让上面的 tick 语义可以被自动验证，状态机被抽成纯 Java 的 `core/SimulationEngine.java`（不依赖 Android），
> Location 字段构造抽成 `core/LocationFields.java`；服务只负责把 tick 结果交给 `MockEngine` 注入。
> `tools/selftest/SimulationSelfTest.java` 用 36 项断言覆盖了上表的每一条行为（含被延迟补齐、暂停无跳变、循环取模、完成保持终点）。
