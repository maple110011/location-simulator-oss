# 04 定位模拟行为规格（单点 / 路线）

## 1. 状态模型（已见）
Mock 状态是不可变数据类 `L0.d`，字段语义由 `toString` 直接给出（`sources/L0/d.java:122-124`）：
```
MockState(
  isRunning: boolean,               // f1367a
  mode: STATIC | ROUTE,             // f1368b，见 L0/b.java:17-23
  isPaused: boolean,                // f1369c
  routeCompleted: boolean,          // f1370d
  currentLocation: LatLng,          // f1371e（WGS84）
  speedMetersPerSecond: double,     // f1372f
  routeDistanceMeters: double,      // g
  routeTotalMeters: double,         // f1373h
  routePoints: List<RoutePoint>,    // f1374i
  errorMessage: String              // f1375j
)
```
- 路线点类型 `L0.f`：RoutePoint(latitude, longitude)（`sources/L0/f.java:4-15`）。
- 采样类型 `L0.c`：MockSample(latLng, speedMetersPerSecond, bearingDegrees)（`sources/L0/c.java:40-42`）。
- 状态由 Service 持有（字段 `g`），初始值 `new d(false, null, null, 0, 0, null, 1023)`（全默认：未运行、STATIC、无点）（`MockLocationService.java:81`）。
- 状态变化后通过回调 `F0.K.b(state)` → `MainActivity` 的 `onMockServiceStateChanged` 同步 UI（`F0/K.java:19-21,33-90`）。

## 2. 两种模拟模式的启动参数（已见）
### 2.1 单点模式（STATIC）
- 入口：`MainActivity.t0(LatLng)`（`MainActivity.java:4361-4406`）。
- 先记一条 HISTORY 记录（协程 `F0/T`：名称取搜索框文本（空则 null），type=HISTORY，insert 到 Room，失败只打日志）（`F0/T.java:52-86`）。
- 检查"模拟位置应用"（AppOps android:mock_location）：`Y()`（`MainActivity.java:1294-1299`）；不通过 → 弹详细设置指南对话框 `k0()` 并中止（:4368-4372）。
- 组 Intent（显式指向 MockLocationService）：
  ```
  action = "START_MOCK"
  extra latitude / longitude (double)
  extra location_name (String，可为 null)
  ```
  SDK≥26 用 startForegroundService，否则 startService；随后 bindService（:4383-4396）。
- Service 侧 `onStartCommand`（`MockLocationService.java:453-469`）：
  1. 没有 latitude/longitude extra → stopSelf 且返回 START_NOT_STICKY(2)。
  2. `g()` 先 startForeground（避免 5 秒 ANR）。
  3. 构造状态 `new d(true, STATIC, latLng, 0.0, 0.0, emptyList, 1004)`（运行中、单点、速度 0、总距离 0、无路线点）。
  4. 立刻注入一次：`a(state, new c(latLng, 0.0f, 0.0f))`——采样速度 0、方位 0。
- 之后每秒 tick 都注入同一个点（速度 0、方位 0），见第 4 节。

### 2.2 路线模式（ROUTE）
- 规划阶段（UI 侧）：路线点列表 `f9467V0`；点地图加点（`MainActivity.y`，见 01 号文档）；速度 `f9469W0` 单位 **km/h**，默认 5.0；循环标志 `f9471X0`（`MainActivity.java:386, 241`）。
- 启动：`MainActivity.v0(C0098s)`（`MainActivity.java:4429-4473`）：
  - 先检查 mock 授权 `Y()`，不通过 → 设置指南对话框。
  - Intent extra：`route_latitudes`(double[])、`route_longitudes`(double[])、`route_speed_mps`(double，**已由 km/h ÷ 3.6 换成 m/s**)、`route_loop`(boolean)；action="START_ROUTE"（:4436-4454）。
  - 数据来源 `F0/A.java:85-88`：`new C0098s(points, f9469W0 / 3.6, f9471X0)`。
- 启动前的订阅/试用闸门见 08 号文档（`F0/A.java:84-102`、`F0/G.java:26-56`）。
- Service 侧（`MockLocationService.java:477-520`）：
  1. 读两个 double[]，成对组装成 LatLng 列表（长度不等时按较短者配对，`j.w0`）。
  2. 校验 `size >= 2 && speed_mps > 0`，否则 `j(new IllegalArgumentException(@string/route_invalid))` → 直接失败收尾（通知消失、服务停止、错误写入状态）。
  3. 把点转成 `List<RoutePoint>`；记录 loop 标志；traveled=0；lastTick=elapsedRealtime。
  4. 计算总长 = 相邻点 haversine 之和；**若 ≤ 0.01 m 也判 route_invalid**（:509-514）。
  5. 起始状态：`mode=ROUTE`、currentLocation=路线首点、速度=speed_mps、routeDistance=0、routeTotal=总长、routePoints=列表（:516-517）。
  6. 首帧采样：位置=首点，速度=speed_mps，方位=`c.x(points, 0.0)` 的 bearing（首段方位）（:517）。

## 3. 1 秒 tick 的精确行为（已见，核心）
实现位置：`sources/A1/o.java:255-308`（Runnable 的 case 3；由 Service 的 `handler.postDelayed(runnable, 1000)` 每 1 秒调度，`MockLocationService.java:202, 118`）。

每 tick 步骤（伪码，语义照抄）：
```
now = SystemClock.elapsedRealtime()
state = service.state
if (!state.isRunning) return                        // 已停止就不再调度
sample = null
if (state.mode == STATIC) {
    if (state.currentLocation != null) sample = MockSample(state.currentLocation, speed=0, bearing=0)
} else {  // ROUTE
    if (points.size() >= 2) {
        dt = (now - lastTick) / 1000.0              // 单位秒，>=0
        lastTick = now                               // 立即更新，保证暂停后恢复不累加空档
        if (!state.isPaused && !state.routeCompleted)
            traveled += state.speedMetersPerSecond * dt   // 只有"运行且未完成"才前进
        total = state.routeTotalMeters
        if (state.loop && total > 0 && traveled >= total)
            traveled = traveled % total               // 循环：取模回到起点
        pos = routePosition(points, traveled)         // 见 02 号文档 4 节
        completed = pos.completed && !state.loop      // 循环模式永不"完成"
        point = pos.point
        sampleSpeed = (!state.isPaused && !completed) ? state.speedMetersPerSecond : 0.0
        newState = state.copy(
             routeCompleted = completed,
             currentLocation = point,
             routeDistance = min(traveled, total))
        service.state = newState
        callback(newState)                            // 同步 UI
        notify(1001, buildNotification())             // 刷新通知进度
        sample = MockSample(point, sampleSpeed, pos.bearingDegrees)
    }
}
if (sample != null) {
    result = inject(sample)                           // 见第 5 节
    if (result is error) fail(result.error)           // 见 09 号文档
}
if (service.state.isRunning) handler.postDelayed(this, 1000)
```
要点（**规格必须照抄的行为**）：
1. **节拍固定 1000 ms，但位移用真实时间差 dt 计算**，不是"每秒固定走 1 秒距离"；后台被延迟时会一次补齐。
2. 暂停（isPaused=true）时仍每秒 tick、仍注入位置（速度 0），只是不累加 traveled；因此恢复后位置与暂停时一致。
3. 循环（loop=true）用"已走距离对总长取模"实现，永不置 routeCompleted。
4. 非循环走完：traveled 被夹到 total，routeCompleted=true，注入的速度为 0，但 **isRunning 仍为 true**（继续每秒注入终点位置）——对应文案 "Route completed · holding final location"（strings.xml:314）。
5. 单点模式不需要任何计算，每秒原样注入（速度 0、方位 0）。
6. 每次 tick 都刷新通知（notification id 1001）。

## 4. Location 对象字段（已见，`MockLocationService.java:89-106`）
```
Location(provider)                     // provider = "gps" 或 "network"
  .setLatitude/  .setLongitude         // 内部 WGS84，直接用（不偏移）
  .setAltitude(0.0)
  .setAccuracy(accuracy)               // gps: 3.0f ; network: 10.0f
  .setTime(System.currentTimeMillis())
  .setElapsedRealtimeNanos(SystemClock.elapsedRealtimeNanos())
  .setBearing(sample.bearingDegrees)   // 路线模式为当前线段方位；单点模式 0
  .setSpeed(sample.speedMPS)           // 路线为设定速度（暂停/完成时 0）；单点 0
若 SDK >= 26 再补：
  .setVerticalAccuracyMeters(accuracy)
  .setSpeedAccuracyMetersPerSecond(0.2f)
  .setBearingAccuracyDegrees(2.0f)
```
两个 provider 的 Location 是完全相同的坐标/速度/方位，只有 provider 名与 accuracy 不同（:309-310）。

## 5. 系统注入方式（已见）
### 5.1 注册/启用测试 provider —— `MockLocationService.c(String)`（:224-232）
```
removeTestProvider(name)                     // 先删，忽略异常
addTestProvider(name,
    requiresNetwork = "network".equals(name),
    requiresSatellite = "gps".equals(name),
    requiresCell = false,
    hasMonetaryCost = false,
    supportsAltitude = true,
    supportsSpeed = true,
    supportsBearing = true,
    powerRequirement = 1,
    accuracy = 1)
setTestProviderEnabled(name, true)
```
进入模拟时对 "gps" 和 "network" 各做一次（:120-133）。失败时汇总成 "No mock provider is available" 或 "Mock provider unavailable"（:167-174）。

### 5.2 每次注入 —— `h(MockSample)`（:303-344）
```
gpsLoc     = build("gps",     sample, accuracy=3.0f)
networkLoc = build("network", sample, accuracy=10.0f)
setTestProviderStatus("gps",     2 /*AVAILABLE*/, null, now)
setTestProviderLocation("gps",     gpsLoc)
setTestProviderStatus("network", 2 /*AVAILABLE*/, null, now)
setTestProviderLocation("network", networkLoc)
若 Google Play services 可用：
    fused = new Location(gpsLoc); fused.setProvider("fused")
    通过 FusedLocationProviderClient 以 Task 形式提交"mock location"（:325-335）
    失败只记结果，不影响主流程
两个 provider 都失败才返回错误 "No mock provider accepted the location"
```

### 5.3 Fused provider（GMS）mock 模式
- 启动注入前：若 GMS 可用 → `setMockMode(true)`（`MockLocationService.java:175-177`；`p070q1/a.java:56` 的 `g(boolean)`）。
- 结束时：`setMockMode(false)`（:219-221）。
- 说明（**已见**）：这是"在 GMS 侧声明本源是 mock，避免 fused 位置覆盖"的常规做法。

### 5.4 清理 —— `b()`（:206-222）
对 "gps"/"network"：`setTestProviderEnabled(false)` + `removeTestProvider`；然后 GMS 可用则 `setMockMode(false)`。

### 5.5 WakeLock（:188-196, 346-357）
- 运行时持有 `PARTIAL_WAKE_LOCK`（flag=1），tag = `<packageName>:MockLocation`，`setReferenceCounted(false)`，`acquire()` 无超时。
- 停止/失败时 release 并置空。

## 6. 运行中控制（已见）
| 操作 | 实现 | 行为 |
|---|---|---|
| 暂停/继续（路线） | `MockLocationService.l()`（:398-412）；UI 按钮 btnPauseRoute、通知按钮 | 仅当 `isRunning && mode==ROUTE && !routeCompleted` 生效；切换 isPaused；同步刷新状态回调与通知；重置 lastTick。**单点模式下此操作无效** |
| 停止 | `k()`（:380-396）；UI btnStop / 通知按钮 STOP_MOCK | 移除 tick 回调、状态重置为默认、清理 provider、释放 WakeLock、stopForeground(true/1)、stopSelf |
| 失败收尾 | `j(Throwable)`（:359-378） | Log.e("MockLocationService","Mock location failed")、状态置 isRunning=false + errorMessage、清理、停止前台与自身 |
| 通知"停止"按钮 | PendingIntent → getService action="STOP_MOCK"（:241） | 同 k() |
| 通知"暂停/继续"按钮 | PendingIntent → action="TOGGLE_ROUTE_PAUSE"（:242） | 同 l() |

## 7. 进度百分比与文案（已见）
- 进度 = `(routeDistanceMeters / routeTotalMeters) * 100` 后 `clamp(0,100)`（`MainActivity.java:539-543`，`K0.f.n` 即 coerceIn）。
- 路线运行文案：@string/route_running_status "%1$.1f km/h · %2$d%%"（strings.xml:329）。
- 暂停文案：@string/route_paused_status "Route paused · %1$d%%"（:325）。
- 完成文案：@string/route_completed "Route completed · holding final location"（:314）。
- 规划中文案：@string/route_planning_status "Planning: %1$d points · %2$.1f km/h"（:327）。
- 按钮文案随状态变：btnStart 在"ROUTE 模式且点数≥2"时显示 "Start Route"，否则 "Start Mock"（`MainActivity.java:579-585`）；btnPauseRoute 文本在 "Pause"/"Resume" 间切换（:564）。

## 8. 边界与校验汇总（已见）
- 路线最少 2 点：UI 侧 `w0()` 提示 "Add at least two route points"（:4475-4481）；Service 侧再次校验（:494）。
- 速度必须 >0（Service）且 ≤300 km/h（UI 对话框）；默认 5.0 km/h。
- 总长必须 >0.01 m（Service）。
- 单点模式要求有选中点，否则 Toast "Please select a point on the map"（:2108-2111）。
- Service 收到 START_MOCK 但没有经纬度 extra → 直接 stopSelf（:455-458）。
- Service `onStartCommand` 返回值：运行中返回 `START_REDELIVER_INTENT(3)`（被杀后系统重投 Intent），否则 `START_NOT_STICKY(2)`（:541-544）。
- 无 Intent 重启（系统重建）：若状态仍在运行 → 重新 startForeground；否则什么都不做（:535-540）。
