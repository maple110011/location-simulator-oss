# 10 无法原样复刻的部分（缺 key / SDK / 账号）

本文件回答任务第 10 项：哪些部分**没有私有 key、签名或第三方账号就无法原样复刻**，以及缺失后的行为后果。

## 1. 百度地图（Baidu Maps SDK）
**已见**：
- Manifest 注入 SDK key：`<meta-data android:name="com.baidu.lbsapi.API_KEY" android:value="@string/baidu_map_key"/>`（`resources/AndroidManifest.xml:54-56`）。
- key 值硬编码在字符串资源：`baidu_map_key = <REDACTED-baidu-sdk-key>`（`resources/res/values/strings.xml:42`）。
- 初始化：`SDKInitializer.setAgreePrivacy(ctx,true); SDKInitializer.initialize(ctx);`（`MainActivity.java:1819-1820`）。
- 百度 SDK 自带授权/校验组件：`com/baidu/lbsapi/auth/LBSAuthManager`、`com/baidu/mshield/*`、`resources/stamp-cert-sha256`、`com.baidu.lbsapi.API_KEY` 需要与 **包名 + APK 签名 SHA1** 绑定。

**缺失后果（推断，基于百度 SDK 通用机制）**：地图瓦片不加载/授权失败、POI 点击与地图交互不可用；但**模拟定位本身不依赖百度地图 SDK**（坐标由用户输入或点击得到后走系统注入），因此"功能复刻"可降级为自绘地图或更换地图 SDK，"原样复刻"不行。

## 2. 百度 LBS Web API 的第二个 AK（硬编码在代码里）
**已见**：`K0/c.java:84` 直接拼 URL 参数 `ak=<REDACTED-baidu-web-ak>`，请求 `api.map.baidu.com/place/v2/search`。
**缺口**：该 AK 属于开发者账号，受配额/包名/域名白名单限制；用自己的 key 才能跑通搜索。缺失时百度分支搜索返回空，回退到系统 Geocoder（见 03 号文档）。

## 3. 谷歌地图（Google Maps SDK for Android）
**已见**：
- `<meta-data android:name="com.google.android.geo.API_KEY" android:value="@string/google_maps_key"/>`（AndroidManifest.xml:57-59）。
- key = `<REDACTED-google-maps-key>`（strings.xml:116）。
**缺口**：Maps SDK key 需要绑定包名+签名、并在 Google Cloud 启用 "Maps SDK for Android"；另需设备有 GMS。缺失时 Google 地图分支不可用，`g0()` 会自动回退百度（:1449-1450）。

## 4. Firebase（项目 mock-location-6c395）
**已见**：
- `google_app_id = 1:785993126910:android:acc9fb4e24590e0cebe6af`（strings.xml:114）
- `google_api_key` / `google_crash_reporting_api_key = <REDACTED-google-api-key>`（:113,115）
- `project_id = mock-location-6c395`（:299）
- `google_storage_bucket = mock-location-6c395.firebasestorage.app`（:117）
- `gcm_defaultSenderId = 785993126910`（:111）
- 使用：Firestore 集合 devices / feedback（06 号文档）；Remote Config 的 5 个开关（同上）；FirebaseInitProvider、RemoteConfigRegistrar 等在 manifest 中注册（AndroidManifest.xml:76-113, 148-153）。
**缺口**：Firestore/Remote Config 需要项目访问权限（安全规则 + API key 允许）。缺自己的 Firebase 项目时：
- 试用判定永远失败（读取异常 → false）→ **所有用户都被订阅闸门拦住**（这是最关键的"行为不可复刻"点）；
- 反馈提交失败（Toast "Submit failed, please try again."）；
- 远程配置全部退回代码默认值（trial 72h 等，见 06 号文档）。
复刻时要么自建后端替换 Firestore，要么本地实现等价试用计时。

## 5. Google Play Billing（订阅）
**已见**：`com.android.vending.BILLING`（manifest:26）；商品 id `mock_location_monthly` / `mock_location_yearly`（MainActivity.java:356）；billing client 8.0.0（manifest:128-130）；价格回退 "US$4.99"/"US$12.99"（strings:417-418）。
**缺口**：
- 商品必须在 Play Console 中真实存在、app 已上架/内部测试，且测试账号已加入许可测试，`queryProductDetails` 才会返回价格；
- 购买/确认/恢复订阅都走 Play 端，无法离线伪造（本地伪造成本高且违反 Play 政策）；
- 缺商品时：订阅弹窗显示回退价，点击购买会失败 → Toast subscription_unavailable → 用户始终无法解锁（除非试用有效）。
复刻建议：把"订阅/试用"抽成可插拔的 Entitlement 接口，用本地逻辑或自有支付替代；但**原样**的 Play 端行为无法复刻。

## 6. Play In-App Review（评价）
**已见**：`ReviewManager.requestReviewFlow()/launchReviewFlow()`（`F0/DialogInterfaceOnClickListenerC0089i.java:104-152`、`F0/C0087g.java:54-83`），需要 Play Store 存在且为官方版本。
**缺口**：无 Play 商店时请求失败，代码只打日志并隐藏按钮；无法复刻"真实弹评价卡片"。

## 7. PairIP 授权壳 / 签名校验
**已见**：
- Application 类为 `com.pairip.application.Application`（AndroidManifest.xml:47）；
- 存在 `com.pairip.licensecheck.LicenseActivity`（:199-201）；
- 声明 `com.android.vending.CHECK_LICENSE` 权限（:218）；
- 存在 `com.android.stamp.*` 元数据与 `resources/stamp-cert-sha256`。
**缺口/影响（推断）**：PairIP 是 Google Play 的分发保护（license + 完整性校验）；APK 被重签后可能触发校验失败（应用退出/功能受限）。**无法**在不掌握原始签名与 Play 授权的情况下原样复刻这一层；复刻工程应移除该层（属于反篡改，不是业务功能）。

## 9. 可复刻性结论
- **核心行为（100% 可复刻，已见）**：双模式模拟、1 秒 tick、路线几何、系统 provider 注入、Location 字段、前台服务+通知+动作、Room 持久化、自检条件、订阅闸门的触发时机与判定顺序。
- **需要替换/自建（不可原样）**：地图渲染（百度/谷歌）、地点搜索（百度 LBS/谷歌 Places/系统 Geocoder）、云端试用与反馈（Firestore）、远程配置、支付、评价、PairIP 保护层。
- **建议的复刻边界**：把地图/搜索/计费/云端做成可插拔接口；把"自检 + 注入引擎 + 路线引擎 + 通知 + 本地存储"作为可 1:1 对齐的核心模块。
