## 5. 搜索管线（已见）
### 5.1 入口与去抖
- 入口：搜索框回车 / 点搜索按钮 → `MainActivity.I(String)`（`MainActivity.java:927-984`）。
- `I()` 行为：
  1. 文本 trim；空 → `F()` 清空并返回。
  2. 关闭键盘、退出搜索态（`J()`）。
  3. 递增请求序号 `f9430A0`（上一次结果用序号比对，**丢弃过期响应**）。
  4. 先尝试"坐标直搜"：把文本按 `,`、空格、`;` 切分，恰好 2 段且都可解析成 double，且纬度∈[-90,90]、经度∈[-180,180] → 直接构造一条本地搜索结果 `I0.n(name="lat, lng", address="lat, lng", lat, lng)` 并显示（:947-981）。
  5. 否则走协程 `F0/C0104y`（:982）。

### 5.2 搜索协程 F0/C0104y（`sources/F0/C0104y.java`）
1. **本地缓存优先**：从 SharedPreferences **"search_cache"** 读键 `query_<小写查询串>`（JSON 数组，元素 {name,address,lat,lng}）；命中则立刻显示（:226-277）。
2. **取当前城市名**：协程 `F0/F` 用 Android 系统 `Geocoder.getFromLocation(当前选中点或真实位置,1)`，取 `Address.getLocality()`，为空取 `getAdminArea()`（`F0/F.java:34-55`）。这个城市名作为搜索区域/城市提示。
3. **调地图实现搜索**：`K0.i.g(query, city, 回调)`：
   - **百度分支**（`K0/d.java:177-180` → `K0/c.java`）：
     - 直接构造 HTTP GET `https://api.map.baidu.com/place/v2/search`，参数 `query=<查询>`、`region=<城市，空则"全国">`、`output=json`、`ak=<REDACTED-baidu-web-ak>`（**硬编码的第二个百度 AK，与 strings 里的地图 SDK AK 不同**）、`scope=2`、`page_size=10`（`K0/c.java:73-90`）。
     - 响应用 `H0.b`（内置 JSON 模型）解析 results；每条取 name + 拼接 address/area/city/province（去空、空格分隔，全空则 "Unknown address"），位置 `c(BD09)→WGS84`（`K0/c.java:103-132`）。
     - 异常或非 2xx → 返回空列表（`K0/c.java:146-149`）。
     - **注意**：这里没有用百度 SDK 的 `PoiSearch`/`SuggestionSearch`，而是自己发 HTTP；`api/BaiduMapService.java` 的 geocodeAddress/searchPoi/searchSuggestion 接口在全工程无实现、无调用（**推断**：早期 Retrofit 方案残余）。
   - **谷歌分支**（`K0/h.g` → `K0/g.java`）：
     - 先用 Android 系统 `Geocoder.getFromLocationName(query,10)` 做本地地理编码（`K0/h.i`，K0/h.java:76-140），有结果就直接返回（WGS84 坐标，不再偏移）。
     - 无结果再请求 `https://maps.googleapis.com/maps/api/place/textsearch/json`，参数 query(必要时拼上城市名)、key=@string/google_maps_key、language=当前语言（`K0/g.java:76-99`）。
     - 响应解析段在 jadx 里出现 ClassCastException/throw null 的失真（`K0/g.java:105-121`），**推断**原意同样把 results 映射成 `I0.n` 列表；无法从产物 100% 确认真实映射字段。
4. **兜底**：地图实现返回空 → 再走 `F0/J`（系统 `Geocoder.getFromLocationName(query,5)`），把每条 Address 的 featureName/thoroughfare/locality 作为名称、thoroughfare/subLocality/locality/adminArea/countryName 逗号拼接作为地址（`F0/J.java:45-99`）。
5. **写缓存 + 显示**：结果非空时取前 5 条（`A3.k.Q(list,5)`）序列化成 JSON 写入 "search_cache" 的 `query_<小写>`；然后 `H(list)` 显示结果（`F0/C0104y.java:159-176`）。全部为空且缓存也空 → 隐藏结果容器并 Toast "No matching locations found"（:177-180）。
6. 序号校验：写缓存/显示前再次比对 `f9430A0`，不一致直接丢弃（:330-334）。
- 文案：strings `search_cached` "Showing recent results"（:341）在代码中没有被引用（推断：缓存命中提示未实现或已被移除）；`search_failed_check_network`（:343）同样未在自有代码里引用（搜遍 sources 未命中）——**推断**网络失败统一走"无结果"分支。

## 6. 逆地理与"城市名"用途（已见）
- `F0/F`：系统 Geocoder 反查"当前选中点/真实位置"的城市名（供百度 place 搜索的 region 参数与谷歌 query 拼接）。
- `K0/h.i`：谷歌分支的本地地理编码（getFromLocationName），返回 GCJ→? 不，返回 WGS84 直用（`K0/h.java:76-140`）。
- 没有任何"输入联想（suggestion/sug）"专用实现：输入框没有 `onTextChanged` 触发搜索的代码，只有"清空按钮显隐"（`F0/N.java`）；百度 SDK 的 `SuggestionSearch` 在本工程中未被调用（**已见**：全 sources 只有 SDK 自身定义）。因此"输入联想"在当前版本**不存在**，搜索是显式提交式。
