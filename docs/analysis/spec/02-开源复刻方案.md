# 开源复刻方案：功能范围、架构与验收标准

本文定义「完整复现」在工程上意味着什么、用什么架构实现、哪些地方允许与原软件不同，以及怎样证明复刻成功。

## 1. 「完整复现」的判定标准

复刻成功的判据不是界面长得一样，而是下面四条同时成立：

1. **能力等价**：把复刻 App 设为模拟位置应用后，另一个普通应用（例如地图或 `adb shell dumpsys location`）读到的 `gps`、`network` 定位就是复刻 App 指定的坐标；Google Play 服务可用时，Fused 定位也被替换。
2. **行为等价**：单点模拟与路线模拟的状态机、1 秒注入节奏、路线速度/循环/暂停/进度/结束语义与原软件一致。
3. **数据等价**：收藏、历史、已保存路线、地图提供商选择、自检完成状态在进程重启后仍然存在，行为与原软件的记录模型对应。
4. **可用性等价**：首次使用有自检与引导；后台运行有前台服务通知与停止/暂停入口；异常（未选中模拟位置应用、权限被拒、注入失败）有明确提示而不是静默失败。

## 2. 原软件 vs 复刻版：差异表

| 能力 | 原软件（2.9.12） | 开源复刻版 | 差异原因 |
|---|---|---|---|
| 系统 mock 注入 | `LocationManager` 测试 provider（gps+network） | 相同 | 无 |
| Fused 定位 mock | 直接 binder 调 GMS（事务 13/85） | 反射调用公开 API `FusedLocationProviderClient.setMockMode/setMockLocation`，设备无 GMS 时自动跳过 | 复刻版不引入 GMS 编译依赖，保持可构建性与开源可移植 |
| 模拟节奏 | 1 秒一次 | 相同 | 无 |
| 路线模拟 | 折线累计距离 + 按速度插值 + 循环/暂停/进度/结束保持 | 相同算法 | 无 |
| 地图渲染 | 百度地图（中国）/ Google 地图（海外），可切换，auto 按地区 | WebView + Leaflet + OpenStreetMap 瓦片为默认；可通过设置切换瓦片源 | 百度/Google 需要私有 API key，且 Google 地图要求 GMS；开源项目不能分发他人 key |
| 地址搜索 | 百度地理编码/POI/联想 | Nominatim（OSM）搜索 + 坐标直输 + 搜索结果缓存 | 同上，无 key 约束 |
| 坐标系 | WGS84 / GCJ-02 / BD-09 可切换 | 相同三种坐标系的输入与显示；内置换算算法 | 原软件用百度 SDK 的 `CoordinateConverter`，复刻版自己实现公开算法 |
| 收藏 / 历史 | Room 表 `mock_location.db`，`Record(type=HISTORY/FAVORITE)` | SQLite 表结构对等（`record` 表，字段 id/name/lat/lng/type/timestamp） | Room 需要额外依赖；复刻版用 `SQLiteOpenHelper`，表结构与语义相同 |
| 已存路线 | 列表 + 命名 + 启动 | 相同 | 无 |
| 自检 | 开发者选项 / 模拟位置应用 / 位置权限 / 通知权限 / 系统定位 / 电池优化 | 相同六项，判定 API 与原软件一致（AppOps `android:mock_location`） | 无 |
| 前台通知 | 标题+坐标+速度、暂停/恢复、停止 | 相同 | 无 |
| 订阅付费 | Play Billing 月/年订阅，未订阅不能开始模拟 | 完全移除，功能免费 | 商业能力不属于模拟定位功能；开源复刻不应携带付费墙 |
| Firebase / 统计 / PairIP | Remote Config、Firestore、安装统计、授权校验 | 全部移除 | 需要 Google Cloud 项目与上架资质，且属于分发与商业能力 |
| 评价弹窗 | 累计成功次数触发 | 保留（本地计数，不跳商店） | 属于交互细节，保留可验证 UI 逻辑 |

## 4. 关键实现约束

1. **不引入无法离线构建的依赖**：只使用 androidx 基础库（appcompat、material、constraintlayout）与本地已有 Gradle 缓存；地图用系统 WebView + 打包在 `assets/` 的 Leaflet，不依赖 Google/百度 SDK。
2. **Fused mock 用反射**：`Class.forName("com.google.android.gms.location.LocationServices")` 成功才启用，行为与公开 API 等价；失败只降级、不崩溃。
3. **服务必须能独立于 UI 存活**：前台服务 + `PARTIAL_WAKE_LOCK` + `START_REDELIVER_INTENT`，与原始实现一致。
4. **坐标系只影响输入与显示**：注入系统的坐标统一按 WGS84 写入（这是原软件的做法：状态与注入都用 `LatLng`，坐标转换只发生在输入/显示/地图 SDK 边界），复刻版保持同一约定，避免「看起来对了但偏差几百米」的经典错误。
5. **可测试性**：`GeoMath`、`RouteEngine`、`CoordinateConverter` 是纯 Java 类，用 JVM 单元测试覆盖，不依赖 Android 运行时。

## 5. 验收清单

### 5.1 单元测试（JVM，`gradle :app:testDebugUnitTest`）

- 距离：北京到上海约 1067 km（±1%）；同一点距离 0；跨 180° 经线不出负数。
- 插值：两点折线 0%、50%、100%、超过终点四种输入的坐标、航向、已走距离。
- 路线：1000 米折线以 10 m/s 推进，t=1s 位置 10 米；暂停 5 秒后恢复，位置不跳变；循环路线跑完总长后回到起点；非循环路线到终点后保持终点。
- 坐标系：WGS84→GCJ-02 在北京市区偏移约 300-700 米且往返误差 < 1 米；GCJ-02→BD-09 再逆变换往返误差 < 1 米。

### 5.2 设备验收（需要一台 Android 机/模拟器）

1. 安装 APK，按引导把 App 设为「模拟位置应用」（设置→开发者选项）。
2. 单点模拟：在地图选点→开始，用另一个地图 App 或 `adb shell dumpsys location` 确认坐标一致（允许米级差异）。
3. 路线模拟：在图上点 3 个以上点、设 30 km/h、开始，确认目标应用里的点沿路线移动，通知里的百分比递增；暂停后位置停住，恢复后继续。
4. 循环：勾选循环，跑完首尾相接的路段后确认回到起点继续。
5. 停止：通知栏「停止」后，目标应用恢复真实定位。
6. 后台：切到后台、熄屏 2 分钟，确认注入未中断（通知仍在，目标应用坐标仍在变化）。
7. 收藏/历史/路线：添加收藏、改名、删除、保存路线、启动已存路线；杀进程重开后数据仍在。
8. 异常：取消「模拟位置应用」授权后开始模拟，应提示去设置而不是静默失败。

## 6. 里程碑

- **M1** 工程骨架 + 构建通过（子代理 build-smith 负责）。
- **M2** 核心引擎：`GeoMath`、`CoordinateConverter`、`RouteEngine` + 单元测试（本人实现）。
- **M3** 前台服务与注入：`MockEngine`、`MockLocationService`、通知与动作（本人实现）。
- **M4** 数据层：SQLite 记录与路线、设置项（本人实现）。
- **M5** UI：地图页、路线规划、收藏/历史/路线/设置、自检（按 analyst 规格实现）。
- **M6** 验收：单元测试全绿 + 设备清单逐条走查，产出 `VERIFY.md` 与截图。
