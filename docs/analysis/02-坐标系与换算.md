# 02 坐标系与换算

## 1. 结论摘要（已见）
App 内部**统一以 WGS84 作为"模拟坐标"的内部表示**：所有"设点"入口最终都把坐标换成 WGS84 存到 `LatLng`，注入给系统的 `Location` 直接用该经纬度；只有在"画到地图上"时，才按当前地图实现分别转成 BD-09（百度）或 GCJ-02（谷歌）。反向（地图点击、百度 POI 结果）则从 BD-09/GCJ-02 转回 WGS84。

- 坐标系枚举：`sources/J0/p.java:20-27` —— WGS84(0)、GCJ02(1)、BD09(2)。
- 换算实现被 jadx 合并进了 `sources/com/google/android/gms/internal/play_billing/AbstractC0323z0.java`（**不是 GMS 官方代码**，是 App 自己的 `CoordinateUtils` 被打散合并的产物；判据：方法签名/注释里出现 "wgsLatLng"/"bdLatLng" 参数名，且被 K0/J0 等自有 UI 类直接调用）。

## 2. 换算公式（已见，均为代码原文的数学等价改写）
### 2.1 中国境内判定
`AbstractC0323z0.java:100-102`
```
I(lat, lng) = lng < 72.004 || lng > 137.8347 || lat < 0.8293 || lat > 55.8271
```
返回 true 表示"在中国境外"（此时所有换算都直接原样返回，不做偏移）。

### 2.2 WGS84 → GCJ-02（火星坐标）
`AbstractC0323z0.java:190-215`（方法 `Z(double lat, double lng)`，返回 GMS 的 LatLng）：
```
dlng = lng - 105.0 ; dlat = lat - 35.0
// 纬度方向的偏移量（原文展开的多项式，核心项如下）
latOff = -100.0 + 2*dlng + 3*dlat + 0.2*dlat*dlat + 0.1*dlng*dlat
       + 0.2*sqrt(|dlng|)
       + (20*sin(6*pi*dlng) + 20*sin(2*pi*dlng)) * 2/3
       + (20*sin(pi*dlat) + 40*sin(pi*dlat/3)) * 2/3
       + (160*sin(pi*dlat/12) + 320*sin(pi*dlat/30)) * 2/3
lngOff = 300.0 + dlng + 2*dlat + 0.1*dlng*dlng + 0.1*dlng*dlat
       + 0.1*sqrt(|dlng|)
       + (20*sin(6*pi*dlng) + 20*sin(2*pi*dlng)) * 2/3
       + (20*sin(pi*dlng) + 40*sin(pi*dlng/3)) * 2/3
       + (150*sin(pi*dlng/12) + 300*sin(pi*dlng/30)) * 2/3
// 椭球参数
a = 6378245.0 ; ee = 0.006693421622965943
magic = 6335552.717000426
lat' = lat + latOff*180 / ((magic / (d2 * sqrt(d2))) * pi)，其中 d2 = 1 - ee*sin^2(lat*pi/180)，sqrt(d2)=sqrt(d2)
lng' = lng + lngOff*180 / ((a / sqrt(d2)) * cos(lat*pi/180) * pi)
```
（代码中 `d18` 即 1-ee·sin²，`dSqrt2` 为其平方根；lat 用 6335552.717000426 而非 a，这是百度系实现的特征。）

### 2.3 GCJ-02 → WGS84（近似逆变换）
`AbstractC0323z0.java:864-873`（方法 `p`）：
```
gcj = Z(wgsGuess)  // 先把输入当作 WGS 正算一遍
wgs = (2*lat - gcj.lat, 2*lng - gcj.lng)
```
即用"两倍输入减一次正算"的一阶近似反解。

### 2.4 WGS84 → BD-09（百度坐标）
`AbstractC0323z0.java:170-190`（方法 `Y`）：
```
gcj = Z(lat, lng)            // 先 GCJ-02
x = gcj.lng ; y = gcj.lat
z = sqrt(x*x + y*y) + 0.00002 * sin(y * pi * 3000/180)
theta = atan2(y, x) + 0.000003 * cos(x * pi * 3000/180)
bd_lat = z*sin(theta) + 0.006
bd_lng = z*cos(theta) + 0.0065
```
（代码里 52.35987755982988 = pi*3000/180。）

### 2.5 BD-09 → WGS84
`AbstractC0323z0.java:277-292`（方法 `c(LatLng bd)`）：
```
x = bd.lng - 0.0065 ; y = bd.lat - 0.006
z = sqrt(x*x + y*y) - 0.00002 * sin(y * pi*3000/180)
theta = atan2(y, x) - 0.000003 * cos(x * pi*3000/180)
gcj_lat = z*sin(theta) ; gcj_lng = z*cos(theta)
返回 p(上述 GCJ) = 2.3 的 GCJ→WGS84 近似逆
```

### 2.6 其他方向
- `a0(wgs)` = WGS84→GCJ-02，返回 GMS LatLng（`AbstractC0323z0.java:218-222`）。
- `w(gcj)` = GCJ-02→WGS84（先 `p` 再包成百度 LatLng 类型）（`AbstractC0323z0.java:913-921`）。
- 所有方法都先判 `I(lat,lng)`，境外直接原样返回。

## 4. 路线几何算法（已见，`sources/p092v1/c.java`）
这些方法被混淆进同一个类，但语义清楚（参数类型是 L0.f = RoutePoint(lat,lng)）：
- **两点距离**（haversine，半径 6371000 m）：`p092v1/c.java:305-314`
  ```
a = sin²(Δlat/2) + cos(lat1)·cos(lat2)·sin²(Δlng/2)
d = asin(sqrt(a)) · 1.2742E7      // 1.2742E7 = 2 × 6371000
```
- **方位角**（起点→终点的初始 bearing，0..360）：`p092v1/c.java:192-197`
  ```
θ = atan2(cos(lat2)·sin(Δlng), sin(lat2)·cos(lat1) - cos(Δlng)·cos(lat2)·sin(lat1))
bearing = (deg(θ) + 360) % 360
```
- **按已行驶距离求折线上的位置**：`p092v1/c.java:452-482`（方法 `x(List<RoutePoint>, double traveled)`）
  ```
若 points.size() < 2 → 抛 IllegalArgumentException("A route requires at least two points")
traveled = max(0, traveled)
for 每条相邻线段 (p1,p2):
    segLen = haversine(p1,p2)
    if segLen > 0.01:              // 忽略重合点，阈值 1 cm
        if traveled <= segLen:
            t = traveled / segLen
            lat = p1.lat + (p2.lat - p1.lat) * t      // 经纬度线性插值（平面近似，非大圆插值）
            lng = p1.lng + (p2.lng - p1.lng) * t
            返回 RoutePosition((lat,lng), bearing(p1,p2), completed=false)
        traveled -= segLen
返回 最后一个点, bearing(倒数第二点→最后点), completed=true
```
- 返回类型 `L0/g`：RoutePosition(RoutePoint point, float bearingDegrees, boolean completed)（`sources/L0/g.java:15-19`）。
- **注意点（推断）**：位置插值用经纬度线性插值，距离用 haversine，两者不完全自洽，长路线/高纬度会出现细微速度偏差；这是原实现的行为，规格复刻时需要照抄才能保持一致。

## 5. 精度与显示格式（已见）
- 界面显示选中点坐标统一 `String.format(Locale.US, "%.6f", ...)`，格式串 @string/coordinates_format "%1$s, %2$s"（MainActivity.java:720-722；strings.xml:87）。
- 通知栏坐标同样 "%.6f, %.6f"（MockLocationService.java:249）。
- 搜索卡片、记录条目同样用 "%.6f, %.6f"（G0/e.java:45；G0/c.java:122）。
- 坐标输入页回填用的是 `String.valueOf(double)` 全精度（J0/r.java:548-554），不是 6 位。
